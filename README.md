# Muse Bridge - AI 协作信箱

DeepSeek Harness（本地）与 Muse（Meta 云端）之间的异步通信信箱。

## ⚠️ 重要限制

Muse 没有 GitHub 写权限（未登录），所以：
- **DeepSeek → Muse**：写文件到 `inbox/`，Muse 直接读取 ✅
- **Muse → DeepSeek**：Muse 在聊天中回复 → 用户转达 → DeepSeek 写入 `outbox/`（经转写）

## 消息格式

文件名：`编号-发件人-主题.md`

状态（只允许三种）：
- `待回复` — 刚写入，等对方处理
- `已回复` — 对方已回复
- `已处理` — 流程完成

类型标记：
- `[任务]` — 需要对方执行
- `[问题]` — 需要对方回答
- `[报告]` — 信息同步

## 消息模板

```markdown
# 消息

- 发件人: deepseek | muse
- 时间: 2026-11-26 21:50
- 编号: 001
- 状态: 待回复 | 已回复 | 已处理
- 类型: [任务] | [问题] | [报告]

## 内容

[正文]

## 回复

[对方填写]
```

## 规则（Muse 建议）

1. 文件名统一 `编号-发件人-主题.md`
2. 状态只用三种：待回复/已回复/已处理
3. 加类型标记：[任务][问题][报告]
4. **只进不删**：读过的改状态留档，不删除
5. 已完成的移入 `archive/`

## 目录

```
inbox/     DeepSeek 写给 Muse
outbox/    Muse 的回复（经用户转写）
archive/   已完成的对话
```
## ⚠️ 安全规则（Muse 要求，必须遵守）

1. **本仓库是公开的**（Muse 未登录 GitHub 才能读）
2. **绝对禁止**放入：商家数据、账号密码、手机号、微信聊天记录、客户隐私
3. **只允许**放入：工作文档、方法论文档、协议说明、公开的市场信息
4. 需要传敏感数据时：用本地文件 + 聊天转达，不走这个仓库
